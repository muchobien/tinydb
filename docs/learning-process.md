# Learning process

For each milestone:

1. **Theory:** Understand the problem and its invariants.
2. **Design:** Specify the binary layout or API before coding.
3. **Implement:** Write the smallest working component.
4. **Test:** Check normal behavior, edge cases, and failure modes.
5. **Inspect:** Examine actual file bytes, query plans, or traces.
6. **Document:** Record design decisions and lessons learned.

Maintain `docs/architecture.md` and a short design note for each major subsystem.

## Guiding principle

**Build the database to understand databases, not just to produce working code.** Each abstraction should solve a problem we have already encountered.
